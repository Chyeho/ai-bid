# AI 标书审核系统 — 前端 设计

## 系统定位

React 19 + TypeScript 单页应用（SPA），面向东莞理工学院财务处采购人员，提供标书上传、AI 审核实时可视化、审核报告导出、知识库管理四大业务模块。

```
用户浏览器
    │
    ▼
┌─ Vite Dev Server (:5173) ─────────────────────────────┐
│  HMR + Proxy: /api → localhost:8086 (Java)             │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ React SPA ───────────────────────────────────────────┐
│                                                        │
│  ┌─────────────────┐  ┌─────────────────────────────┐ │
│  │ Redux Toolkit    │  │ TanStack React Query         │ │
│  │ (Auth State)     │  │ (Server State + Cache)       │ │
│  └─────────────────┘  └─────────────────────────────┘ │
│                                                        │
│  ┌──────────────────────────────────────────────────┐ │
│  │ 核心页面                                           │ │
│  │                                                    │ │
│  │  Dashboard ─→ BidUpload ─→ BidAudit(Detail) ─→ Report │
│  │      │                        │                    │ │
│  │      ├── IssueList            ├── AuditAssistant   │ │
│  │      └── Library              └── PDFPreview       │ │
│  └──────────────────────────────────────────────────┘ │

```

## 技术选型

| 层 | 技术 | 选型理由 |
|---|---|---|
| 框架 | React 19 | 最新稳定版，Server Components 预备 |
| 类型 | TypeScript (strict) | 全栈类型安全 |
| 构建 | Vite 6 | HMR 极快，ESBuild 预构建 |
| 路由 | React Router v7 | `createBrowserRouter` + 嵌套路由 |
| 全局状态 | Redux Toolkit | 仅用于 Auth（token + userInfo），够用不重 |
| 服务端状态 | TanStack React Query v5 | 缓存/去重/乐观更新/SSE 集成 |
| UI 组件库 | Ant Design 5.27 | 企业级中后台标配，Table/Form/Modal 开箱即用 |
| 样式方案 | antd-style (CSS-in-JS) | 自动适配 Ant Design 主题 Token + 暗色模式 |
| HTTP | Axios | 拦截器链（token 注入 + 401 处理 + 错误统一提示） |
| 图表 | ECharts 6 | 饼图 + 柱状图，百度出品，中文场景支持好 |
| PDF 渲染 | react-pdf 10 | 逐页渲染 + 自定义图层（高亮/bbox） |
| Markdown | react-markdown + remark-gfm | 报告预览 + AI 对话回复 |
| SSE | fetch + ReadableStream (原生) | 审核进度 + AI 对话流式推送 |

> **为什么用 Redux Toolkit + React Query 两套？** Redux 只管登录状态（token 存取、401 跳转），React Query 管所有 API 数据的缓存和刷新。混用是刻意为之——Auth 是全局同步状态（需要拦截器读取 token），审核数据是异步服务端状态（需要缓存/stale 管理），两者模型不同，各用各的最佳工具。

## 1. 路由设计

```
/login                              public (RouteGuard: 已登录则重定向)
/                                   protected (RouteGuard: 未登录则跳 /login)
  /dashboard                        首页工作台（默认重定向目标）
  /upload/:projectId                标书上传
  /bidReview                        审核列表
  /bidReview/detail/:id             审核详情（核心页面：PDF + 分析 + AI 对话）
  /bidReview/issues/:id             问题清单（独立全屏视图）
  /bidReview/report/:id             审核报告（A4 预览 + DOCX 导出）
  /library                          知识库管理
```

### 路由鉴权 — RouteGuard

```
RouteGuard({ requireAuth: true })
    │
    ├── requireAuth=true + 未登录 → Navigate to /login (state.from = 当前路径)
    ├── requireAuth=false + 已登录 → Navigate to /dashboard
    └── 其他 → <Outlet />
```

### 代码组织：Feature-based 路由

每个功能模块导出自己的路由对象，在 `app/router.tsx` 中统一组装：

```typescript
// app/router.tsx
import { loginRoutes } from '@/features/login/routes';
import { dashboardRoutes } from '@/features/dashboard/routes';
// ...

createBrowserRouter([
  loginRoutes,        // { path: '/login', element: <LoginPage /> }
  {                   // 受保护路由
    element: <RouteGuard requireAuth />,
    children: [
      { element: <MainLayout />, children: [
        { index: true, element: <Navigate to="/dashboard" /> },
        ...dashboardRoutes,
        ...bidUploadRoutes,
        ...bidAuditRoutes,
        ...bidLibraryRoutes,
      ]}
    ]
  }
]);
```

## 2. 状态管理：三层分离

### 第一层：Auth（Redux Toolkit）

```
Redux Store
  └── authSlice
        ├── token: string | null        ← localStorage (remember me) / sessionStorage
        ├── userInfo: { id, username, realName }
        └── isAuthenticated: boolean

动作:
  setCredentials({ token, userInfo })    ← 登录成功
  logout()                               ← 登出 / 401 / token 过期
  restoreAuth()                          ← 应用初始化时从 storage 恢复
```

**token 存取策略**：
- "记住我" 勾选 → `localStorage`（浏览器关闭后保留）
- 不勾选 → `sessionStorage`（浏览器关闭后清除）

### 第二层：服务端数据（TanStack React Query）

```typescript
// lib/queryClient.ts
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,     // 5 分钟内不重新请求
      retry: 1,
      refetchOnWindowFocus: false,   // 避免频繁切换窗口时重复请求
      placeholderData: (prev) => prev, // 翻页时保留旧数据，避免闪烁
    },
  },
});
```

每个 API 模块导出 `queryOptions` 对象，组件通过 `useQuery` / `useMutation` 消费：

```typescript
// 列表查询
const { data, isLoading } = useQuery(dashboardOptions.list());

// 翻页 — params 变化自动重新请求
const { data } = useQuery(auditListOptions.queryList({ page, size, name }));

// 变更 — 成功后刷新关联缓存
const uploadMutation = useMutation({
  mutationFn: uploadBid,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['bids'] }),
});
```

### 第三层：URL 状态（useUrlState）

所有列表页的筛选条件（页码、搜索关键词、Tab 切换）存储在 URL 查询参数中：

```
/bidReview?page=2&size=20&name=东莞理工&category=工程类
```

好处：
- 刷新页面保留筛选状态
- 可复制链接分享当前视图
- 浏览器前进/后退可用

```typescript
// hooks/useUrlState.ts
const [filters, setFilters] = useUrlState({
  page: 1,           // number 自动 parse
  size: 20,
  name: '',
});
```

### 为什么不用 Zustand / Jotai？

- Redux Toolkit 已在项目中使用，无需引入第二个全局状态库
- 大量状态是服务端数据（标书列表、审核结果、对话历史），React Query 比状态库更适合
- URL 状态覆盖了剩余的筛选参数场景

## 3. API 层

### Axios 实例 + 双拦截器

```
请求拦截器:
  从 storage 读取 token → 自动注入 Authorization: Bearer {token}

响应拦截器:
  ├── 成功 (2xx): 解包 response.data，直接返回业务数据
  ├── 401: dispatch(logout()) → 清除 storage → 跳转 /login
  ├── Blob 响应: 返回 response.data（文件下载/预览）
  └── 其他错误: 提取 error.response.data.message → Ant Design message.error()
```

### SseClient — 统一的 SSE 连接工具

项目中有两类 SSE 流，共用相同的底层模式：

| SSE 流 | 端点 | 用途 |
|--------|------|------|
| 审核进度 | `GET /api/audit-tasks/{taskId}/stream` | Agent 进度、实时 Findings、阶段切换 |
| AI 对话 | `POST /api/chat/stream` | 流式思考过程 + 工具调用 + 最终回答 |

```
connectStream(url, headers, callbacks):
    │
    ├── fetch(url, { headers: { Authorization, Last-Event-ID } })
    ├── reader = response.body.getReader()
    ├── 逐行解析 SSE 协议:
    │     "event: issue\n"         → callbacks.onIssue(JSON.parse(data))
    │     "event: progress\n"      → callbacks.onProgress(JSON.parse(data))
    │     "event: complete\n"      → callbacks.onComplete()
    │     "id: 42\n"              → 更新 lastEventId（断线重连回放起点）
    └── 连接断开 → 自动重连（携带 Last-Event-ID）
```

### 代理配置（Vite）

```typescript
// vite.config.ts
server: {
  host: '127.0.0.1',
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://127.0.0.1:8086',   // Java 后端
      changeOrigin: true,
    },
    '/api/chat/stream': {
      target: 'http://127.0.0.1:8086',
      selfHandleResponse: true,           // 关键: 不透传缓冲，直接 pipe SSE
      configure: (proxy) => {
        proxy.on('proxyRes', (proxyRes, req, res) => {
          // 设置 SSE 响应头: text/event-stream, no-cache, keep-alive
          // 处理上游错误 → 502
          // 客户端断开 → 销毁上游连接
        });
      },
    },
  },
},
```

> **`selfHandleResponse: true` 为什么重要？** 默认代理会缓冲完整响应后再转发，这对 SSE 是致命的——SSE 需要逐事件推送，缓冲意味着前端永远收不到进度。`selfHandleResponse` 接管管道，每收到一个 chunk 立即 flush 到客户端。

## 4. 核心页面详设

### 4.1 审核详情页（最复杂页面）

这是整个前端的核心——用户在这里看到标书 PDF + AI 实时分析。

```
┌─ DetailPage ───────────────────────────────────────────────┐
│ ┌──────────────────────┐ ┌───────────────────────────────┐ │
│ │                      │ │  Tab: 审核过程 │ 审核结果 │ 智能问答 │ │
│ │                      │ │ ┌───────────────────────────┐ │ │
│ │   PDF 预览            │ │ │ ClauseActivityMap         │ │ │
│ │   (react-pdf)         │ │ │ (章节树 + 实时状态灯)       │ │ │
│ │                      │ │ ├───────────────────────────┤ │ │
│ │   · 文字高亮（风险条款）│ │ │ PipelineProgress          │ │ │
│ │   · BBox 矩形框       │ │ │ (阶段: 上传→解析→审核→汇总)  │ │ │
│ │   · 点击跳转页码      │ │ ├───────────────────────────┤ │ │
│ │   · Ctrl+滚轮缩放     │ │ │ AgentProgressCards        │ │ │
│ │                      │ │ │ (7 个 Agent 并行进度条)     │ │ │
│ │                      │ │ ├───────────────────────────┤ │ │
│ │                      │ │ │ LiveReviewFeed            │ │ │
│ │                      │ │ │ (ReAct 步骤实时滚动)        │ │ │
│ │                      │ │ └───────────────────────────┘ │ │
│ └──────────────────────┘ └───────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

**三种 PDF 高亮策略**：

```typescript
// hooks/usePdfFlow.ts — VITE_HIGHLIGHT_MODE 控制
type HighlightMode = 'auto' | 'bbox' | 'text';

// auto (默认):
//   优先使用 Block BBox 坐标 ← GET /api/audit-tasks/{id}/blocks
//   失败则降级为文本搜索: 在页面文本中定位 source_quote → 计算字符级高亮区域

// bbox:
//   仅使用后端返回的 BBox 矩形框（最精确，需 Rust pdfplumber 支持）

// text:
//   仅使用文本匹配（兼容性最好，无需 BBox 数据）
```

**审核生命周期（useAuditTask Hook）**：

```
1. 创建任务:
   POST /api/audit-tasks { bidId }
   → taskId

2. 建立 SSE 连接:
   GET /api/audit-tasks/{taskId}/stream
   → 实时事件流

3. SSE 事件处理:
   ┌─ phase       → 更新 PipelineProgress 当前阶段
   ├─ progress    → 更新总体进度百分比
   ├─ agent_progress → 更新 AgentProgressCards
   ├─ trace       → 追加到 LiveReviewFeed
   ├─ issue       → 追加到 AnalysisList + ClauseActivityMap
   ├─ stats       → 更新统计数字
   └─ complete    → 停止 SSE，展示最终结果

4. 兜底轮询（SSE 断开时的安全网）:
   setInterval(3s):
     GET /api/audit-tasks/{taskId}        ← 状态
     GET /api/audit-tasks/{taskId}/result  ← 结果
```

**本章节树（ClauseActivityMap）**：

```
将标书的 Section 树转化为 Ant Design Tree，每个节点显示：
  · 标题（如 "第二章 供应商资格要求"）
  · 状态灯: ○ 待审 / ◉ 审查中 / ● 已完成
  · 风险标记: 🔴3 🟡2   （该章节发现的风险数量）
  · 点击节点 → PDF 跳转到对应页码
```

### 4.2 AI 对话（AuditAssistant）

```
┌─ ChatWindow ────────────────────────────┐
│  ┌──────────────────────────────────┐   │
│  │ 消息历史 (react-markdown 渲染)      │   │
│  │                                    │   │
│  │ [User]: 这个条款是否违反政府采购法？  │   │
│  │                                    │   │
│  │ [AI]: 💭 思考中...                  │   │
│  │   ├─ 🔍 搜索: "政府采购法 供应商资格"  │   │
│  │   ├─ 📖 查阅: 《政府采购法》第22条    │   │
│  │   └─ ✅ 结论: 该条款合规...          │   │
│  │       📎 引用: [法规原文链接]         │   │
│  └──────────────────────────────────┘   │
│  ┌──────────────────────────────────┐   │
│  │ [输入框________________] [发送]    │   │
│  └──────────────────────────────────┘   │
└──────────────────────────────────────────┘
```

**流式对话实现（useAiChat Hook）**：

```
POST /api/chat/stream { projectId, bidId, content, selection? }
    │
    ├── SSE event: "thinking"
    │   → 追加思考步骤到当前消息（💭 展开动画）
    │
    ├── SSE event: "tool_call"
    │   → 追加工具调用记录（🔍 搜索了什么 / 📖 查阅了什么）
    │
    ├── SSE event: "answer"
    │   → 累积最终回答文本（打字机效果）
    │   → 包含 citations（法条链接、案例引用）
    │   → 包含 confidence（置信度百分比）
    │
    └── SSE event: "done"
        → 消息完成，保存到 localStorage (key: aiChat:v3:{projectId}:{bidId})
```

**消息持久化**：使用 `localStorage` 而非后端数据库作为主存储。后端 `/api/chat/history` 作为备份查询。这样对话即刻响应、离线可读。

**DOCX 导出流程**：

```
GET /api/audit-tasks/{taskId}/report → Markdown 内容
    │
    ▼
前端渲染 Markdown → HTML (react-markdown)
    │
    ▼
html-docx-js-typescript → 生成 .docx Blob
    │
    ▼
file-saver → 浏览器下载
```

> **为什么前端生成 DOCX 而非后端？** 用户可实时预览 A4 效果 + 勾选章节后即时看到变化，如果后端生成需要每次调整都重新请求，交互延迟太高。

## 5. 主题系统

### 暗色模式

```
theme-provider.tsx
    │
    ├── 读取 localStorage 'theme' → 'light' | 'dark' | 'system'
    ├── system 模式: matchMedia('(prefers-color-scheme: dark)') 监听系统变化
    ├── 切换时: document.documentElement.classList.toggle('dark')
    └── Ant Design ConfigProvider theme={ antdTheme }
```

antd-style 的 `createStyles` 自动读取 Ant Design Token，所有组件样式无缝跟随主题切换——无需写两套 CSS。

## 6. 响应式策略

| 断点 | 布局变化 |

## 9. 性能与优化策略

| 策略 | 说明 |
|------|------|
| React Query 缓存 | 列表数据 5 分钟 stale，避免重复请求 |
| placeholderData | 翻页时保留旧数据，新数据返回后无缝替换 |
| React.lazy | 路由级代码分割（未来优化项，当前未启用） |
| PDF 逐页渲染 | react-pdf 按需渲染可见页，非一次性加载全部 |
| SSE 内存管理 | SSE 事件批量处理，`LiveReviewFeed` 限制最大 500 条 |
| localStorage 配额 | 对话历史使用 `aiChat:v3:` 前缀隔离，支持清除 |
