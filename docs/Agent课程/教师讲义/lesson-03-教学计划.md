# 第3课教学计划：Agentic RAG

---

## 教学目标

区分"传统 RAG（检索是硬编码步骤）"和"Agentic RAG（检索是 Agent 的一个工具）"。学员用关键词匹配实现文档搜索，不引入向量数据库。

---

## 教学内容安排

### 0-10min：上周回顾

- 展示 tool calling 作业：Agent 自主选择工具的 demo

### 10-35min：概念讲解

**核心对比**（重点）：

```
传统 RAG（死板）：用户问题 → [必须检索] → [必须回答]
Agentic RAG（智能）：用户问题 → Agent 判断 → 需要查？→ 搜索 → 基于结果回答
                                       → 不需要？→ 直接回答
```

演示：同一个 Agent，问"今天天气"→直接回答；问"政府采购法第22条"→先搜文档再回答。学员直观看到区别。

### 35-50min：技术要点

- 文档预处理：段落切分策略（双换行切，≤300字/段）
- 关键词搜索算法：分词 → 去停用词 → 命中计数 → 排序
- 搜索结果格式：`{ "results": [{ "title", "snippet", "score" }] }`

### 50-60min：作业说明

- 提供 3 个 txt 文件，学员不用自己找
- 搜索工具作为一个新的 Tool 实现，注册到第 2 课的 ToolRegistry
- **关键要求**：Agent 自己决定何时搜索——System Prompt 要写清"涉及具体法规/条款时先搜索，常识性问题直接回答"

---

## 学员常见坑

| 坑 | 怎么帮 |
|---|---|
| 搜索结果总是空 | 检查分词逻辑：中文不能按空格分，需要至少按标点分 |
| 每段 300 字不知道怎么算 | `s.chars().count()` 不是 `s.len()` |
| 相关性分数总是 1.0 或 0.0 | 提示用 `命中词数 / 总词数` |
| Agent 每轮都搜索 | System Prompt 加入决策规则 |

---

## 评分标准

| 项 | 权重 | 怎么检查 |
|---|---|---|
| 编译 | 30% | `cargo check` |
| 搜索返回合理结果 | 25% | 搜"供应商资格"→ 返回政府采购法相关段落 |
| Agent 自主决定搜索 | 20% | 问常识 → 不搜索；问法规 → 搜索 |
| 回答引用了搜索内容 | 15% | Agent 回复中能看出是基于文档回答 |
| 思考题 | 10% | |

## 与项目的关联

让学员看 `backend-rust/src/agents/tools/search_document.rs`——他们实现的是关键词匹配简化版，项目用的是 BGE-M3 向量检索。概念完全一致：都是"根据查询返回相关文档段落"。
