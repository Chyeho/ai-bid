# 教师讲义 — 教学指南

> 本文档只给看。学生只看 `学生讲义/` 下的内容。

---

## 一、课程设计理念

### 核心原则

1. **不提供封装**：学员不 import 任何现成 Agent 框架。LLM 调用使用自己写的 `ai-client` crate（Rust 大作业），Agent 逻辑每个组件亲手实现
2. **概念先行、代码在后**：周一发布讲义，学员周中写代码，周四提交，周五答疑
3. **每课在前一课基础上累加**：第 1 课用的 ai-client → 第 2 课加 tool calling → 第 3 课加搜索 → ... → 第 7 课完整的 Multi-Agent + Memory 系统
4. **与项目代码呼应**：每课最后点明"你刚写的 X 对应项目中的 Y"，让学员看到学习与工作的连接

### 学员不学什么

- 不会学 LangChain / AutoGen / CrewAI 等框架（学了 Python 框架对写 Rust 没用）
- 不会学 prompt engineering 技巧（那是 G5 领域工具组的事）
- 不会学 embedding / 向量数据库细节（太深，项目中有专门组负责）

---

## 二、每周教学流程

```
周一     发布讲义 + 作业，学员自学
周中     学员完成代码作业（约 2-4 小时）
周四     作业截止提交
周五     集中答疑 + 讲评（30 分钟）
```

---

## 三、你需要准备的材料

每节课你需要提前准备：

| 材料 | 说明 | 耗时 |
|---|---|---|
| **starter 代码** | 能 `cargo check` 通过，有 TODO 标记 | ~30min/课 |
| **solution 代码** | 完整可运行参考实现 | ~30min/课 |
| **参考输出示例** | 学员作业的期望输出 | ~15min/课 |
| **示例文档**（第3课需要） | 政府采购法.txt + 招标投标法.txt + 示例标书.txt | 一次性 |

### starter 代码设计原则

- 能编译通过（`cargo check` 无错）
- 运行时能看到 TODO 提示（如 `println!("TODO: 实现对话循环")`）
- TODO 标记清晰，每个标记不超过 20 行需补全
- 不给答案，但给方向（如注释中写 `// 提示：用 ai-client 的 client.chat() 方法`）

## 四、作业评分机制

### 评分维度

| 维度 | 权重 | 说明 |
|---|---|---|
| 编译通过 | 30% | CI 自动检查，不通过直接 0 分 |
| 功能正确 | 40% | 手动测试：给定输入 → 检查输出 |
| 代码质量 | 20% | `cargo clippy` 无 warning |
| 思考题 | 10% | 用自己的话回答（防 AI 生成） |

### 批改策略

- 编译：CI 自动跑，不通过打回
- 功能：准备 3 个测试用例，逐一验证
- 质量：跑一遍 clippy，人工扫一眼命名和结构
- 思考题：只要不是明显复制粘贴的，都算通过

## 五、学员管理

### 分组建议

按 Rust 水平分为两档：

| 档位 | 判断标准 | 作业要求 |
|---|---|---|
| 基础档 | Rust 语法刚学完，async/.await 不熟 | 完成基本要求即可 |
| 进阶档 | 能熟练写 async Rust | 基本要求 + 至少 1 个进阶挑战 |

### 常见问题预案

| 问题 | 预案 |
|---|---|
| 学员说"太难了做不出来" | 降低到基础档要求，给更多提示，安排结对编程 |
| 学员用 ChatGPT/Copilot 生成全部代码 | 判为不合格，要求重写 + 口头解释代码逻辑 |
| 学员说"这和项目有什么关系" | 每课结尾指出对应项目的哪个文件，让学员去读 |
| 学员进度严重落后 | 1v1 补课 30 分钟，跳过后面的进阶挑战 |
