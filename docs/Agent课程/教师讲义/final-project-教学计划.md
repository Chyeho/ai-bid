# 毕业设计教学计划：Mini 标书审核 Agent

> 2 周，学员独立完成。目标是验证他们能把 7 周的知识组装成完整系统。

---

## 设计意图

### 为什么选"标书审核"作为大作业

1. **与项目直接对应**：学员完成的 Mini 版，就是 ai-bid 项目的简化原型
2. **覆盖所有知识点**：LLM 调用、Tool Use、RAG、Planning、Multi-Agent（选做）、Memory
3. **有明确的评判标准**：找没找到风险、引没引用法规——客观可衡量

### 和项目的差距

学员做的是**单 Agent + 关键词搜索**版本，项目是**11 Agent + 向量检索 + 图记忆**。但核心流程完全一致：解析条款 → 逐条审核 → 调用工具 → 输出风险 → 汇总报告。学员做完这个再看 coordinator.rs 就能说"我明白了"。

## 你需要准备的材料

### 测试标书（关键）

准备 1 份 `.txt` 文件，约 500-1000 字，含 **6 条条款**（5 个故意埋入的问题 + 1 条灰色地带条款）：

| 条款 | 埋入的问题 | 期望风险等级 | 对应法规 |
|---|---|---|---|
| 投标保证金 | 金额为投标总价的 5% | **high** | 政府采购法实施条例第33条（上限2%） |
| 技术规格 | 指定"联想品牌" | **high** | 政府采购法第22条（不得限定品牌） |
| 付款方式 | 验收后 180 天付款 | **medium** | 政府付款期限一般 30 天内 |
| 格式条款 | 缺盖章要求 | **low** | 格式规范要求 |
| 正确条款 | 无问题 | **none** | — |

### 法规库

提供 3 个 txt（和第 3 课相同即可）：
- `政府采购法.txt`（全文）
- `政府采购法实施条例.txt`
- `招标投标法.txt`

## 评分细节

### 功能正确性（25%）— 如何测试

```powershell
# 测试命令
cargo run -- review 测试标书.txt

# 检查点
1. 是否输出了 5 条条款的结果
2. 是否标记了保证金条款为高风险
3. 是否标记了品牌限定为高风险
4. 每条风险是否有 reason 字段（不是空的）
5. report.json 是否存在且格式正确
```

### 风险检出率

评分标准：
- 检出 4 个埋入问题 = 满分 25%
- 检出 3 个 = 20%
- 检出 2 个 = 15%
- 检出 1 个 = 10%
- 检出 0 个 = 5%（至少程序能跑）

> 注意：学员可能检出我们没埋入的问题（如 Agent 认为某条款有问题但我们觉得没问题）。这是合理的——真实标书审核中确实存在主观判断。只要理由充分，也算正确检出。

### 法规引用（15%）

- 高风险发现必须有法规引用（`law_ref` 字段不为空）
- 引用可以来自 `search_document` 搜索结果
- 不要求法条号完全精确（学员用的是关键词搜索不是向量检索，精度有限）

## 常见问题预案

| 问题 | 预案 |
|---|---|
| Agent 对所有条款都判 no_risk | System Prompt 太弱。提示："你是严格的法律审核专家，宁可错杀不可放过。遇到任何可能的违规都要标记。" |
| LLM 输出格式不稳定（有时 JSON，有时文本） | 提示用第 4 课的 `clean_json()` 函数。如果实在解析不了，允许用文本格式（灵活处理） |
| 搜索太慢（法规文件太大，每次全文扫描） | 不扣分。提示可以预建索引（HashMap<关键词, 段落>） |
| 学员说"两周做不完" | 砍 scope：不要求漂亮的终端输出，不要求 Multi-Agent，只要求跑通 + 检出 2 个风险 |
| 学员直接用项目的 react_loop.rs | 不算作弊——能看懂并正确使用项目代码说明他真的理解了。但要求他口头解释代码逻辑 |

## 与大作业之后的关系

大作业完成后，学员进入项目实际开发。此时他们应该能：

1. 看懂 `react_loop.rs` 的 while 循环 → 对应大作业的逐条审核循环
2. 看懂 `tools/mod.rs` 的 ToolRegistry → 对应自己写的 Tool trait
3. 看懂 `coordinator.rs` 的 7 阶段流水线 → 对应大作业的 Phase 1→2→3
4. 看懂 `prompts.rs` 的 System Prompt → 对应自己调的 prompt

**建议安排**：大作业提交后，组织一次"代码走读会"——让学员对比自己的代码和项目代码，说说哪些一样、哪些不同。这是从"学习"到"工作"的桥梁。
