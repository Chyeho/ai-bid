# 第7课：Memory — 让 Agent 拥有记忆

> Agent 关了再开就失忆？这节课让它记住你。

---

## 学习目标

1. 理解 Agent 记忆的三层模型：工作记忆 → 短期记忆 → 长期记忆
2. 实现对话历史的滑动窗口和自动摘要
3. 实现跨对话持久化的用户偏好

---

## 核心概念

### 三层记忆模型

```
工作记忆（Working Memory）
  = 当前对话的完整消息列表
  生命周期：程序运行期间
  问题：消息太多 → 超过 LLM 的 token 上限（约 13 万 tokens ≈ 10 万字）

短期记忆（Short-term Memory）
  = 对旧消息的摘要
  生命周期：当前对话
  做法：消息超 20 条 → 前一半调 LLM 摘要 → 删掉原文 → 用 2-3 句话替代

长期记忆（Long-term Memory）
  = 跨对话持久化的关键信息
  生命周期：永远（存文件）
  做法：用户说"我喜欢详细解释" → Agent 提取偏好 → 写入 JSON 文件
       下次启动 → 自动加载 → 注入 System Prompt
```

### Token 上限问题

Qwen-Plus 最大支持约 13 万 tokens。当对话超过这个数时 API 报错。即使不报错，历史太长也会：
- 让 LLM "分心"（注意力被旧消息稀释）
- 每次请求都发送完整历史 → 成本越来越高

解决方案：**滑动窗口 + 摘要**。旧消息不直接发，而是发一条摘要替代。

### 三层记忆对比

| | 工作记忆 | 短期记忆 | 长期记忆 |
|---|---|---|---|
| 存什么 | 完整消息 | 摘要文本 | 结构化偏好 |
| 存哪里 | 内存 Vec | 内存 String | JSON 文件 |
| 生命周期 | 单次程序运行 | 单次对话 | 跨对话持久 |
| 什么时候更新 | 每轮对话 | 超过 20 条消息时 | 检测到新偏好时 |

## 作业

### 基本要求

给第 5 课或第 6 课的 Agent 代码加上记忆：

**1. 短期记忆**

- 消息超过 20 条时，取前半部分调 LLM 生成摘要
- 删掉已摘要的原始消息（`Vec::drain`）
- 在对话历史开头插入一条 `[对话历史摘要] ...`
- 规则：1 个中文字 ≈ 2 tokens，消息数估算即可，不要求精确计算

**2. 长期记忆**

- 设计 `UserMemory` 结构体（含 `Vec<Preference>`），支持 JSON 序列化
- 每 5 轮对话，调 LLM 提取用户偏好（如"回答风格：详细"、"关注领域：政府采购法"）
- 偏好存入 `memory/{user_id}.json`
- 下次启动对话时加载偏好，注入 System Prompt

**3. 验证**

- 第 1 次对话：告诉 Agent "我喜欢详细的解释，带代码示例"
- 关闭程序
- 第 2 次对话：问同样的问题 → Agent 自动用详细风格回答

### 进阶（选做）

- **记忆淘汰**：长期记忆超过 10 条时，调 LLM 判断哪些过时了可以删
- **冲突处理**：用户说"我喜欢简答"但之前记录是"喜欢详细"→ LLM 判断以哪个为准
- **语义搜索记忆**：对长期记忆做简单索引，支持"我们之前聊过关于 Rust 的什么？"

### 思考题

> 你们项目的 `session_graph.rs` 本质也是一个记忆系统——记录每个条款被哪个 Agent 审查过、发现什么风险。这种"结构化记忆"和本课的"对话历史记忆"有什么本质不同？各自适合什么场景？
