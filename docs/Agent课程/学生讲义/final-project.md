# 毕业设计：Mini 标书审核 Agent

> 2 周，把 7 周学到的东西组装成一个完整系统。

---

## 你要做什么

实现一个**命令行标书审核工具**：

```
$ cargo run -- review 招标文件.txt

🔍 正在分析标书...
📋 发现 6 条条款，开始逐条审核...

[1/6] 条款：投标保证金
  🤖 Agent 思考：需要查法规...
  🔧 调用工具：search_document("政府采购法 保证金 比例")
  📖 找到：《政府采购法实施条例》第33条
  ⚠️ 发现风险：保证金比例 5%，超过法定上限 2%
  ✅ 审核完成

[2/6] 条款：付款方式
  ...

========================================
审核报告
========================================
高风险 2 条:
  - 保证金超标 (违反政府采购法第33条)
  - 品牌限定 (指定"联想"品牌，涉嫌排他)

中风险 1 条:
  - 付款周期过长

低风险 1 条:
  - 格式不规范

无风险 1 条

详见 report.json
```

## 工作流程

### 输入

一个 `.txt` 文件，包含一段标书文本（讲师提供，约 500-1000 字，含 3-5 个故意埋入的问题）。

格式示例：

```
==========
条款1：投标保证金
投标人须在投标截止时间前缴纳投标保证金，金额为投标总价的5%。
==========
条款2：技术规格
本项目采购的计算机设备指定为联想品牌...
==========
条款3：付款方式
项目验收合格后180天内支付全部款项。
==========
```

### 处理流程

```
Phase 1: 解析
  读入文件 → 按 "==========" 分割成条款列表

Phase 2: 逐条审核（核心）
  for 每条条款:
    Agent 收到条款文本 + "你是政府采购审核专家，请审核..."
    Agent 自主决定：
      → 需要查法规？调用 search_document("相关法条")
      → 找到了 → 基于法条判断风险等级
      → 没找到 → 基于常识判断
    Agent 输出：{ risk_level: "high/medium/low/none", reason: "...", law_ref: "..." }

Phase 3: 汇总报告
  合并所有审核结果
  按风险等级排序（high → medium → low → none）
  输出文本报告 + report.json
```

### 输出

1. **终端实时日志**：每条条款审核时打印 Agent 的思考过程和工具调用
2. **report.json**：结构化审核结果

```json
{
  "total_clauses": 6,
  "high_risk": [
    {
      "clause_id": 1,
      "clause_text": "投标保证金...",
      "risk_type": "保证金超标",
      "reason": "保证金比例5%，超过《政府采购法实施条例》第33条规定的2%上限",
      "law_ref": "政府采购法实施条例 第33条"
    }
  ],
  "medium_risk": [...],
  "low_risk": [...],
  "no_risk": [...]
}
```

## 提示

- 不要试图一次写完。先让一条条款能审出来，再加循环
- System Prompt 是关键。花时间调 prompt，比写更多代码有效
- 法规库用第 3 课的搜索工具，讲师会给几份核心法规的 txt
- 如果 Agent 一直不调用搜索工具，检查 prompt 里有没有说"遇到法规问题先搜索"
- 如果 LLM 输出格式不稳定，参考第 4 课的结构化 JSON 处理技巧

### 关于 Memory（第 7 课应用）

- 审核结果保存到 `audit_history/{文件名}.json`，再次审核同一文件时加载历史结果
- 输出报告中标注"上次审核：X 条风险（2026-07-11）"和"本次新增：Y 条"
- 这样同一份标书反复审核时，不会重复报告已发现的问题

### 进阶（选做）：MCP 集成

- 把 `search_document` 工具做成一个独立的 MCP Server（参考第 6 课）
- Agent 通过 MCP Client 连接 Server 进行法规搜索
- 这个不算基础分，但会显著提升你的架构设计能力
