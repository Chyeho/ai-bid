# 第3课：Agentic RAG — 带检索能力的 Agent

> Agent 不再只靠"记忆"回答，它学会了自己去翻文档。

---

## 学习目标

1. 理解 RAG：先检索相关文档，再让 LLM 基于文档回答
2. 理解 Agentic RAG：Agent **自己决定**什么时候检索、检索什么
3. 实现本地文档搜索工具

---

## 核心概念

### 传统 RAG vs Agentic RAG

```
传统 RAG（死板）：
  用户问题 → [必须检索] → [必须基于检索回答]
  问题："你好，今天天气怎么样？" → 也去搜文档，浪费时间

Agentic RAG（智能）：
  用户问题 → Agent 分析："需要查资料吗？"
    ├─ 不需要 → 直接回答
    └─ 需要 → search_document("关键词") → "够了吗？"
              ├─ 够了 → 基于结果回答
              └─ 不够 → 换个关键词再搜
```

区别在于：**检索不再是硬编码的步骤，而是 Agent 的一个工具**。Agent 自己判断要不要用、怎么用。

### RAG 三步曲

```
检索（Retrieve）
  Agent 调用 search_document("政府采购法 供应商资格")
  → 返回 Top-5 最相关的文档段落

增强（Augment）
  把搜索到的段落追加到对话上下文
  "以下是搜索到的相关信息：\n[段落1]\n[段落2]..."

生成（Generate）
  LLM 基于用户原始问题 + 检索到的段落 → 生成答案
  "根据《政府采购法》第22条，供应商应..."
```

### 本课的搜索怎么实现

不引入向量数据库（太重），用关键词匹配：

1. 把文档切成段落（按双换行切，每段 ≤ 300 字）
2. 用户搜索词拆成关键词（去掉标点、过滤单字）
3. 命中关键词的段落 → 按命中数排序 → 取 Top-5

## 作业

### 基本要求

在第 2 课的基础上：

1. **准备文档**：在项目中放 3 个 `.txt` 文件（讲师会给：政府采购法、招标投标法、一份示例标书）
2. **实现 `SearchDocument` 工具**：
   - 实现 `Tool` trait
   - `execute` 时加载文档 → 关键词搜索 → 返回 `{ "results": [...] }` JSON
   - 每条结果包含：文档标题、匹配段落（≤300字）、相关性分数（命中词数/总词数）
3. **更新 System Prompt**：告知 Agent 何时应该搜索文档（涉及具体法规/条款时），何时直接回答（常识性问题）
4. **验证**：问 Agent "政府采购法对供应商资格有什么要求？"→ Agent 应先调 `search_document` → 再基于结果回答

### 进阶（选做）

- 实现 BM25 排序（更准确的相关性计算）
- 搜索结果标注来源：Agent 回答时标明信息出自哪个文档
- 多轮检索：Agent 搜一次不满意，换关键词再搜

### 思考题

> 什么场景下你会选择 Agentic RAG 而不是传统 RAG？传统 RAG 有什么 Agentic RAG 没有的优势吗？
