> 本文档是《项目架构设计》的补充，定义各阶段的交付目标、时间安排、组间解耦策略。
> 架构总览、分组职责、接口 Schema 见主文档。

## MVP 范围声明

**MVP = 审招标文件**（单文档合规审核）。先做审招标文件，稳定后扩展审投标文件，最后做招投标全流程对照审核。

```
Phase 1-2: 审招标文件 ──→ 第一个可 Demo 的产品
Phase 3:   + 审投标文件 ──→ 双文档独立审核
Phase 4:   + 招投标全流程 ──→ 招标+投标对照审核 + 知识飞轮完整闭环
```

| 阶段 | 审核对象 | 审核逻辑 | 知识库需求 |
|---|---|---|---|
| **MVP (Phase 1-2)** | 招标文件 | 单文档合规：条款合法性、排斥性条款、评分合理性 | 政府采购法规、学校采购常见问题 |
| **Phase 3** | + 投标文件 | 单文档完整性：资质响应、参数偏离、漏项、格式 | + 行业资质标准、产品参数库 |
| **Phase 4** | + 招投标全流程 | 双文档对照：招标要求 vs 投标响应逐条比对 | + 废标案例库、历史审核数据 |

**G2 行业聚焦**：MVP 阶段聚焦**学校财务部门经常审理的采购类型**——办公设备、信息化建设、物业管理、教材图书、实验室设备、食堂采购、校园维修工程、安保服务。本质上属于"政府采购"体系下的教育行业采购。

### G4 在 Phase 2 的简化策略（关键）

现有代码已经实现了 7 阶段 Pipeline + 11 个 Agent + 并发调度 + AgentBus + SessionGraph + BlindSpot 动态 Agent。**Phase 2 不做从零搭建，而是做减法**。

**砍掉（Phase 3/4 再说）**：

| 功能 | 现有代码位置 | 砍掉原因 |
|---|---|---|
| Scout 阶段 | `coordinator.rs:scout_phase()` | MVP 文档长度可控，不需要预扫描 |
| Debate 阶段 | `coordinator.rs:debate_high_risk()` | 3-Agent Pipeline 不需要正反方辩论 |
| BlindSpot 阶段 | `coordinator.rs:run_blind_spot()` | 动态发现新风险类型对 MVP 过度 |
| Agent 并发执行 | `coordinator.rs:execute_agents()` tokio::spawn | 串行更可控，先跑通再并行 |
| AgentBus 消息广播 | `bus.rs` | 串行 Pipeline 不需要 Agent 间实时通信 |
| SessionGraph 复杂边 | linked_to/cites/contradicts/same_law | 保留基础 has_risk+reviewed_by |
| 动态 Agent 生命周期 | `coordinator.rs:load_dynamic_agents()` | MVP 规则表固定 |

**保留**：

| 功能 | 用途 |
|---|---|
| 核心 Pipeline：Route → Execute → Merge → Triage | MVP 主链路 |
| ReAct Loop 单 Agent 内工具调用循环 | JudgeAgent 的核心执行方式 |
| 结构化 JSON 输出（output_finding 工具） | 保证下游可消费 |
| ReviewEventBus SSE 事件流 | 前端实时进度展示 |
| Trace 日志（JSONL） | 调试 Prompt 和工具调用 |

**G4 的具体工作**：

| 周次 | 工作 | 产出 |
|---|---|---|
| W1-2 | 深度阅读现有代码，画出调用链路图，理解每个 Pipeline 阶段的输入/输出 | 代码理解文档（内部） |
| W3 | 编写精简版 Coordinator：config 中只启用 3 个 Agent，砍掉 Scout/Debate/BlindSpot 阶段 | 可运行的精简 Pipeline |
| W4 | 集成 G2 规则引擎 HTTP API（RuleAgent 调用 G2）+ 集成 G3 知识检索 HTTP API（JudgeAgent 调用 G3） | Agent ↔ G2/G3 联调通过 |
| W5 | 与 G5 联调（注入新 Prompt + 工具），与 G8/G9 全链路联调 | 端到端审核报告产出 |

### G2 学校采购行业聚焦（8 大类）

| 大类 | 典型采购项目 | 核心法规 | 常见问题 |
|---|---|---|---|
| **办公设备** | 电脑、打印机、家具、空调 | 政府采购品目分类目录 | 技术参数倾向性（指定品牌/型号） |
| **信息化建设** | 校园网络、智慧教室、管理系统 | 《政务信息系统政府采购管理办法》 | 评分标准不透明、软件著作权要求过高 |
| **物业管理** | 保洁、绿化、安保、维修 | 《物业管理条例》 | 资质要求与项目规模不匹配 |
| **教材图书** | 教材供应、图书馆配书 | 《出版管理条例》 | 指定出版社、限制供应商 |
| **实验室设备** | 仪器、试剂、实验台 | 《政府采购进口产品管理办法》 | 进口产品审批、技术参数排他 |
| **食堂采购** | 食材供应、食堂承包 | 《食品安全法》《学校食品安全与营养健康管理规定》 | 供应商资质、食品安全标准 |
| **校园工程** | 装修、改造、小型基建 | 《招标投标法》《必须招标的工程项目规定》 | 资质要求、工程量清单、付款条件 |
| **安保服务** | 保安、监控、消防 | 《保安服务管理条例》 | 资质要求、人员持证 |

### Phase 2 检查标准

- [ ] 上传 5 份真实学校采购招标文件，每份输出 ≥ 10 条审核发现

- [ ] 前端能展示审核报告（问题列表 + 原文高亮定位）

## G3 知识库冷启动策略

### Phase 1-2 知识获取路线

**目标**：在 Phase 2 开始前拥有 ≥ 1500 条可检索的法规/案例切片。

**获取方式（按优先级）**：

| 优先级 | 来源 | 获取方式 | 预估数量 | 适用场景 |
|---|---|---|---|---|
| P0 | 政府采购法及实施条例 | 官网下载 → 按条款切片 | ~200 条 | 所有审核 |
| P0 | 招标投标法及实施条例 | 官网下载 → 按条款切片 | ~150 条 | 工程类审核 |
| P0 | 财政部政府采购规章（74号令/87号令/94号令等） | 财政部官网下载 | ~300 条 | 程序合规 |
| P1 | 各省政府采购负面清单 | 省级政府采购网下载 | ~500 条 | 排斥性条款检测 |
| P1 | 学校采购相关地方规章 | 教育厅/财政厅网站下载 | ~200 条 | 教育行业专项 |
| P2 | 财政部投诉处理决定 | 中国政府采购网公告 | ~200 条 | 废标案例 |
| P2 | 住建部标准施工招标文件范本 | 住建部官网下载 | ~100 条 | 工程类审核 |

**处理流程**：
```
原始文档（PDF/HTML/Word）
  → 格式清洗（去页眉页脚、去广告、去导航）
  → 按条款/章节切片（保持法条完整性，每片 200-800 字）
  → BGE-M3 向量化（1024d，本地 ONNX）
  → 写入 Qdrant（含元数据：来源、版本、生效日期、适用行业）
```

**MVP 阶段不做**：联网搜索兜底（Phase 3 再加）。Phase 2 只依赖本地知识库，避免网络延迟和 API 消耗。
