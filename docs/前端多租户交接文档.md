## 2. 统一约定

- 外部 API 基础路径是 `/api`，请求和 JSON 响应使用 UTF-8。
- 受保护接口发送 `Authorization: Bearer <token>`。
- 浏览器不得发送 `X-Tenant-Id`。该请求头只用于 Java 到 Rust 的内部调用。
- 租户 API 的 `tenant_id`、`user_id`、`member_id`、`owner_user_id` 使用十进制字符串。前端内部也统一按 `string` 保存，不能用 JavaScript `number` 做主键。
- `tenant_id` 出现在路径或切租户请求体时，只是请求切换到哪个候选租户。服务端仍以 Bearer 会话、Redis Session、成员关系和租户状态解析 `CurrentTenant`。
- `role`、`permissions`、`is_current` 只用于页面展示和按钮显隐，不是前端授权依据。
- 租户域接口的错误判断使用 HTTP 状态和 `data.error_code`，不要匹配中文 `msg`。

统一 JSON 外壳：

```json
{
  "code": 200,
  "msg": "success",
  "data": {},
  "timestamp": 1786019400123
}
```

错误响应仍使用同一外壳。`request_id` 要保留下来，后端排查需要它：

```json
{
  "code": 403,
  "msg": "当前角色无权执行该操作",
  "data": {
    "error_code": "TENANT_ROLE_FORBIDDEN",
    "request_id": "8b9c0e7f-9d8b-4f86-b77d-9a3d4c2f5001",
    "details": {
      "required_permission": "tenant.members.role.write"
    }
  },
  "timestamp": 1786019400123
}
```

## 3. M2 已合入的认证接口

当前基线已有的 Java 控制器路径：

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| POST | `/api/auth/login` | JSON：`username`、`password` | `Result<AuthSession>` |
| POST | `/api/auth/refresh` | Bearer；无请求体 | `Result<AuthSession>`；旧令牌失效 |
| POST | `/api/auth/logout` | Bearer；无请求体 | `Result<void>`；`data` 为空 |
| POST | `/api/auth/switch-tenant` | Bearer；JSON：`tenant_id` | `Result<AuthSession>`；旧令牌失效 |

登录请求：

```json
{
  "username": "alice",
  "password": "<password>"
}
```

当前基线的切租户请求：

```json
{
  "tenant_id": "20002"
}
```

切换成功后，服务端递增 `session_version`、签发新令牌并返回完整会话。并发中的旧请求可能收到 `401 TENANT_SESSION_STALE`，处理方式见第 8 节。

### 3.1 AuthSession 的真实字段

`login`、`refresh`、当前基线的 `switch-tenant` 都把下列对象放在 `data` 中：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "token_type": "Bearer",
  "expires_in": 86400,
  "session_version": 3,
  "user_info": {
    "user_id": "10001",
    "username": "alice",
    "real_name": "Alice"
  },
  "current_tenant": {
    "tenant_id": "20001",
    "tenant_code": "acme-bid",
    "name": "Acme 招标团队",
    "status": "ACTIVE",
    "role": "ADMIN",
    "permissions": ["tenant.read", "tender.write"],
    "is_current": true
  },
  "tenants": [
    {
      "tenant_id": "20001",
      "tenant_code": "acme-bid",
      "name": "Acme 招标团队",
      "status": "ACTIVE",
      "role": "ADMIN",
      "permissions": ["tenant.read", "tender.write"],
      "is_current": true
    }
  ]
}
```

- `token` 只保存在认证状态中，调用业务接口时写入 `Authorization: Bearer ${token}`。
- `expires_in` 是服务端给出的秒数，不要据此生成或修改 `session_version`。
- `session_version` 只保存和比较，不由前端递增。
- 没有 ACTIVE 成员时，`current_tenant` 为 `null`，`tenants` 为空；业务接口会返回 `400 TENANT_REQUIRED`。
- tenant-v1 约定 `user_info.real_name`。当前 `UserInfoVO` 的 Java 字段名是 `realName`，源码只给 `user_id` 加了 JSON 注解；联调看原始响应，适配层可暂时兼容 `real_name ?? realName`，页面统一使用 `real_name`。

### 3.2 冻结契约中的切租户路径

tenant-v1 还冻结了：

```text
POST /api/tenants/{tenantId}/switch
Authorization: Bearer <token>
```

请求体为空，响应是 `AuthSession`。目标租户不是当前用户成员时返回 `404 TENANT_NOT_FOUND`。该路径仍待验收；前端继续通过适配层调用当前已合入的 `/api/auth/switch-tenant`，不要在页面层维护两套路径。

## 4. 租户和成员接口

M3 已合入主线。以下 GET/POST 和成员列表接口可以按当前租户会话使用；成员角色更新/移除、邀请和契约切租户接口仍待验收，不在本节的已就绪范围内。

### 4.1 租户列表、创建和当前租户

| 方法 | 路径 | 请求 | `data` 真实字段 |
|---|---|---|---|
| GET | `/api/tenants` | Bearer；当前 M3 控制器没有必填查询参数 | `current_tenant_id`、`items` |
| POST | `/api/tenants` | Bearer；JSON：`name` 必填，`tenant_code`、`plan_code`、`settings` 可选 | 完整 `Tenant` |
| GET | `/api/tenants/current` | Bearer | `TenantSummary`；没有当前租户时 `400 TENANT_REQUIRED` |

`GET /api/tenants` 示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "current_tenant_id": "20001",
    "items": [
      {
        "tenant_id": "20001",
        "tenant_code": "acme-bid",
        "name": "Acme 招标团队",
        "status": "ACTIVE",
        "role": "ADMIN",
        "permissions": ["tenant.read", "tender.write"],
        "is_current": true
      }
    ]
  },
  "timestamp": 1786019400123
}
```

`TenantSummary` 字段：`tenant_id`、`tenant_code`、`name`、`status`、`role`、`permissions`、`is_current`。

`POST /api/tenants` 请求允许的字段：

```json
{
  "name": "Acme 招标团队",
  "tenant_code": "acme-bid",
  "plan_code": "STANDARD",
  "settings": {
    "timezone": "Asia/Shanghai"
  }
}
```

前端不能提交 `owner_user_id`、`status`、`version` 或 `tenant_id`。创建成功后当前用户成为唯一 `OWNER`。`Tenant` 在摘要字段上增加 `owner_user_id`、`plan_code`、`settings`、`version`、`created_at`、`updated_at`。

当前实现不读取 OpenAPI 中列出的 `page`、`size`，前端不要依赖这两个参数。契约正文称 `GET /api/tenants/current` 返回 `session_version`，但 OpenAPI 的 `TenantSummary` 和当前 VO 都没有该字段；前端继续从 AuthSession 读取 `session_version`。

## 5. 前端本地状态

登录、刷新、切租户成功后整体替换 AuthSession，不要拆开更新令牌和租户字段：

```ts
type AuthState = {
  token: string | null;
  token_type: "Bearer" | null;
  expires_in: number | null;
  session_version: number | null;
  user_info: { user_id: string; username: string; real_name?: string | null } | null;
  current_tenant: TenantSummary | null;
  tenants: TenantSummary[];
};

type TenantSummary = {
  tenant_id: string;
  tenant_code: string;
  name: string;
  status: "ACTIVE" | "DISABLED" | "DELETED";
  role: "OWNER" | "ADMIN" | "AUDITOR" | "MEMBER" | "VIEWER";
  permissions: string[];
  is_current: boolean;
};
```

- 令牌优先放在内存中；若刷新页面后仍要保持登录，可使用 `sessionStorage`，退出时同步清空。不要把令牌写入 URL、日志或埋点。
- `current_tenant` 是服务端快照；下拉框尚未提交的选择放在临时变量 `switchTargetId` 中。
- `tenants` 只是候选列表。切换成功后以新 AuthSession 的 `tenants` 和 `current_tenant` 覆盖旧值。
- 查询缓存带租户命名空间，例如 `["tenant", tenantId, "projects"]`。这样可以避免缓存串租户，但不能替代服务端授权。
- 切租户删除旧租户的 `Last-Event-ID`、SSE 连接、未完成请求和业务缓存；新租户连接从无游标开始。

## 6. 业务接口和真实响应字段

M3、M4 已合入主线。旧业务 VO 仍返回 camelCase 字段，tenant-v1 的租户字段使用 snake_case。下面按已就绪范围列出接口；明确未完成的隔离能力放在各小节末尾和第 12 节。

### 6.1 KnowledgeFile

控制器基础路径：`/api/knowledge-files`。KnowledgeFile 的数据库查询、下载、预览已经按当前租户过滤，存储路径带租户前缀。

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| GET | `/api/knowledge-files` | 查询参数：`category`、`tags`、`applicable_scope`、`sortBy` 默认 `asc`、`page` 默认 `1`、`size` 默认 `10` | `Result<PageResult>` |
| GET | `/api/knowledge-files/search` | 查询参数：`keyword`、`sortBy`、`page`、`size` | `Result<PageResult>` |
| POST | `/api/knowledge-files/upload` | multipart：`file`、`category` 必填；`fileName`、`tags`、`applicable_scope`、`description`、`status` 可选 | 成功时 `data` 为空 |
| PUT | `/api/knowledge-files/{fileId}` | multipart：`category` 必填，其余字段同上传，`file` 可选 | 成功时 `data` 为空 |
| PATCH | `/api/knowledge-files/{fileId}/status` | JSON：`{"status": 1}` | 成功时 `data` 为空 |
| DELETE | `/api/knowledge-files/{fileId}` | 无请求体 | 成功时 `data` 为空 |
| GET | `/api/knowledge-files/{fileId}/download` | 无请求体 | 二进制；不存在 404 |
| GET | `/api/knowledge-files/{fileId}/preview` | 无请求体 | PDF 二进制；不支持类型 415 |

列表的 `data` 是旧 `PageResult`，字段只有 `total` 和 `records`，不是 tenant-v1 的 `page/size/items`。`KnowledgeFileVO` 字段：`id`、`fileName`、`fileSize`、`fileType`、`category`、`tag`、`description`、`applicableScope`、`status`、`version`、`uploadUserId`、`uploadUserName`、`uploadTime`、`updateTime`。请求参数叫 `tags`，响应字段叫 `tag`。

```json
{

  "msg": "success",
  "data": {
    "total": 1,
    "records": [
      {
        "id": 501,
        "fileName": "采购制度.pdf",
        "fileSize": "1.2MB",
        "fileType": "PDF文件",
        "category": "制度",
        "tag": "采购类",
        "description": "采购制度",
        "applicableScope": "procurement",
        "status": "启用",
        "version": 1,

### 6.2 Project

控制器基础路径：`/api/projects`。同步创建、查询、更新、删除已按租户隔离，并校验父子关系。

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/api/projects` | JSON `ProjectDTO`；`projectName` 非空 | `Result<ProjectVO>` |
| PUT | `/api/projects` | JSON `ProjectDTO`；`id` 必填 | `Result<ProjectVO>`；不存在 404 |
| DELETE | `/api/projects/{id}` | 无请求体 | 成功时 `data` 为空 |
| GET | `/api/projects` | 无必填查询参数 | `Result<ProjectVO[]>`，包含聚合信息 |
| GET | `/api/projects/my` | 无必填查询参数 | `Result<ProjectVO[]>`，当前用户项目 |

`ProjectVO` 字段：`id`、`userId`、`projectName`、`supplierName`、`parseStatus`、`latestVersion`、`createTime`、`updateTime`、`fileCategory`、`auditResult`、`tenders`。

`tenders` 中的每一项都是 `TenderWithAuditVO`，字段只有 `tender`、`auditTask`、`auditReport`。这三个字段目前是 Java 实体对象，不是冻结的前端 VO，页面应按可空对象处理。

### 6.3 Tender

控制器基础路径：`/api/bid-documents`。同步创建、查询、更新、删除已按租户隔离，并校验父子关系。Tender 物理路径的租户前缀仍待验收，因此文件路径隔离不列入已就绪能力。

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/api/bid-documents/upload` | multipart：`file` 必填，其他字段绑定 `TenderDTO` | `Result<TenderVO>` |
| GET | `/api/bid-documents` | 查询参数绑定 `TenderPageQueryDTO` | `Result<PageResult>`，`data` 为 `total`、`records` |
| GET | `/api/bid-documents/stats` | 查询参数绑定 `TenderPageQueryDTO` | `Result<TenderStatsVO>` |
| GET | `/api/bid-documents/{id}` | 无请求体 | `Result<TenderVO>` |
| GET | `/api/bid-documents/project/{projectId}/versions` | 无请求体 | `Result<TenderVO[]>` |
| GET | `/api/bid-documents/projects` | 无请求体 | `Result<TenderProjectVO[]>` |
| DELETE | `/api/bid-documents/{id}` | 无请求体 | 成功时 `data` 为空 |
| GET | `/api/bid-documents/{id}/download` | 无请求体 | PDF/Word 预览或原文件二进制 |

`TenderVO` 字段：`id`、`fileName`、`filePath`、`fileSize`、`fileType`、`fileCategory`、`bidName`、`supplierName`、`budgetAmount`、`pageCount`、`parseStatus`、`uploadUserId`、`uploadTime`、`version`、`projectId`、`auditorName`、`auditResult`。

`TenderProjectVO` 字段：`projectId`、`projectName`、`createTime`、`creatorName`、`latestVersion`、`supplierName`、`fileCategory`、`auditorName`。`TenderStatsVO` 字段：`allCount`、`unreviewedCount`、`completedCount`。`filePath` 只能当元数据，下载必须走 `/download`。

### 6.4 AuditTask

控制器基础路径：`/api/audit-tasks`。同步创建、查询、更新、删除已按租户隔离，并校验父子关系。AuditIssue、Report、Chat、Trace，以及异步 AuditEngine 首次 `loadTask` 和队列上下文仍待验收；SSE 的旧会话失效与事件回放（stale/replay）按 M5 暂缓。

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/api/audit-tasks` | JSON `CreateAuditTaskRequest` | `Result<AuditTaskCreateVO>` |
| GET | `/api/audit-tasks/{taskId}` | 无请求体 | `Result<AuditTaskStatusVO>` |
| POST | `/api/audit-tasks/{taskId}/recover` | 无请求体 | `Result<boolean>` |
| GET | `/api/audit-tasks/{taskId}/result` | 查询参数：`page` 默认 1、`size` 默认 20、`sinceIssueNo` 可选 | `Result<ResultVO>` |
| GET | `/api/audit-tasks/{taskId}/stream` | `Accept: text/event-stream`、Bearer、`Last-Event-ID` 可选 | SSE，不是 `Result` |
| GET | `/api/audit-tasks/count-audit` | 无必填查询参数 | `Result<Map<string, number>>` |
| GET | `/api/audit-tasks/{taskId}/blocks` | 查询参数：`ids` 必填 | `Result<RustBlockBBoxResponse[]>` |
| POST | `/api/audit-tasks/callback` | 查询参数：`taskId`；原始请求体 | 后端回调，不是浏览器页面接口 |

创建响应只有 `taskId`。状态响应字段：`taskId`、`status`、`stage`、`progress`、`issueCount`、`failedStages`、`totalFileCount`、`pendingFileCount`、`processingFileCount`、`failedFileCount`。

`blocks[]` 字段：`blockId`、`page`（从 0 开始）、`pageWidth`、`bbox`；`bbox` 包含 `x0`、`top`、`x1`、`bottom`，坐标单位是 PDF 点。

结果响应 `ResultVO` 字段：`taskId`、`auditResult`、`summary`、`routingSummary`、`graphSnapshot`、`issues`。`summary` 和 `routingSummary` 的字段是 `totalIssues`、`critical`、`high`、`medium`、`low`、`info`、`totalClauses`、`agentClauseCounts`、`legalVerifyCount`、`blindSpotFindings`。

`issues[]` 字段：`issueNo`、`riskId`、`severity`、`isCritical`、`criticalReason`、`category`、`agentName`、`description`、`location`、`suggestion`、`reference`、`sourceQuote`、`legalBasis`、`caseRefs`、`confidence`、`anchorQuote`、`anchorPage`、`anchorSection`、`anchorTokens`、`anchorCharsRange`、`noRisk`、`initialTier`、`finalTier`、`tierEscalated`、`truncated`、`clauseIds`、`blockIds`、`citations`、`suggestedAgent`、`agent`。`location` 是 `pageNumber`、`sectionName`、`context`；`citations[]` 是 `title`、`url`、`siteName`；`suggestedAgent` 是 `agentName`、`agentPrompt`、`sectionKeywords`、`reason`。

    "percent": 42,
    "message": "正在审查"
  }
}
```

连接路径是 `GET /api/audit-tasks/{taskId}/stream`，必须带 Bearer；`event_id` 同时是 SSE 的 `id` 和 JSON 字段。断线后使用同一令牌和 `Last-Event-ID` 重连；切租户或会话失效后删除旧游标，不能只改 URL 中的租户值。服务端的旧会话失效与事件回放（stale/replay）仍暂缓。

## 7. tenant_id 的边界

前端可以把服务端返回的 `tenant_id` 作为字符串显示，也可以用于路由参数、缓存键和切租户请求。其他业务请求必须遵守以下限制：

- 禁止发送 `X-Tenant-Id`，或把它当成授权请求头。
- 禁止给业务请求额外添加 `tenant_id` 查询参数或请求体字段来指定数据域。
- 禁止把本地保存的 `tenant_id`、`role`、`permissions` 当成授权来源。
- 禁止只修改 URL 中的租户、任务、文件或文档 ID 来访问另一个租户。
- 不用 `user_id` 或 `uploadUserId` 代替租户过滤。

服务端决定 CurrentTenant；不存在或不属于当前租户的资源统一按 404 处理，前端不要通过错误差异探测其他租户是否存在。

## 8. 统一错误处理

所有请求先解析 `response.status`、`body.data.error_code` 和 `body.data.request_id`。程序分支只看 HTTP 状态和 `error_code`：

| HTTP / error_code | 统一动作 |
|---|---|
| 401 `AUTH_REQUIRED`、`AUTH_INVALID` | 多个失败请求共用一次刷新操作；刷新失败时清空认证状态和租户缓存，再跳转登录页。 |
| 401 `TENANT_SESSION_STALE` | 不重放旧请求。切租户已返回新会话时，等待状态写入后用新令牌重试一次；否则只刷新一次。删除 SSE 旧游标后再重连。 |
| 403 `TENANT_ROLE_FORBIDDEN`、`TENANT_OWNER_REQUIRED` | 保留会话，不重试；隐藏或禁用无权限动作。 |
| 403 `TENANT_CONTEXT_INVALID` | 停止操作并重新读取会话，不自行补请求头或 tenant_id。 |
| 404 `TENANT_NOT_FOUND` | 重新拉取租户列表，撤销本地候选选择。 |
| 404 `RESOURCE_NOT_FOUND` | 清除资源或列表项缓存，显示不可见/不存在；不换 ID 重试。 |
| 404 `TENANT_MEMBER_NOT_FOUND` | 刷新成员列表，不把它当成创建成员信号。 |
| 400 `TENANT_REQUIRED` | 不重试业务请求；有 ACTIVE 租户就走切租户，没有则显示创建租户或无租户状态。 |

## 9. axios / fetch 拦截器伪代码

### 9.1 axios

```ts
const raw = axios.create({ baseURL: "/api" });
const api = axios.create({ baseURL: "/api" });
let refreshInFlight: Promise<AuthState> | null = null;

api.interceptors.request.use((config) => {
  const { token } = authStore.getState();
  if (token) {
    config.headers = config.headers ?? {};
    config.headers.Authorization = `Bearer ${token}`;
  }
  // 不设置 X-Tenant-Id。
  return config;
});

async function refreshOnce() {
  if (!refreshInFlight) {
    const token = authStore.getState().token;
    if (!token) throw new Error("AUTH_REQUIRED");
    refreshInFlight = raw.post("/auth/refresh", null, {
      headers: { Authorization: `Bearer ${token}` },
    }).then((res) => {
      const session = res.data.data as AuthState;
      authStore.replace(session);
      return session;
    }).finally(() => { refreshInFlight = null; });
  }
  return refreshInFlight;
}

api.interceptors.response.use(undefined, async (error) => {
  const config = error.config ?? {};
  const status = error.response?.status;
  const code = error.response?.data?.data?.error_code;
  const isAuthCall = (config.url ?? "").includes("/auth/");
  const canRefresh = status === 401 &&
    ["AUTH_REQUIRED", "AUTH_INVALID", "TENANT_SESSION_STALE"].includes(code) &&
    !config._authRetried && !isAuthCall;
  if (canRefresh) {
    config._authRetried = true;
    await refreshOnce();
    return api.request(config);
  }
  handleTenantError(status, code, error.response?.data?.data?.request_id);
  throw error;
});
```

`raw` 不挂同一个响应拦截器，避免刷新接口再次触发刷新。生产代码还要使用 AbortController 或请求代数，防止旧租户的慢响应覆盖新租户页面。

### 9.2 fetch

```ts
async function fetchApi(input: RequestInfo, init: RequestInit = {}, retried = false) {
  const headers = new Headers(init.headers);
  const token = authStore.getState().token;
  if (token) headers.set("Authorization", `Bearer ${token}`);
  const response = await fetch(input, { ...init, headers });
  if (response.ok) return response;
  const body = await response.clone().json().catch(() => null);
  const code = body?.data?.error_code;
  const isRefresh = String(input).endsWith("/auth/refresh");
  if (response.status === 401 && !retried && !isRefresh &&
      ["AUTH_REQUIRED", "AUTH_INVALID", "TENANT_SESSION_STALE"].includes(code)) {
    await refreshOnce();
    return fetchApi(input, init, true);
  }
  handleTenantError(response.status, code, body?.data?.request_id);
  throw new ApiError(response.status, code, body);
}
```

### 9.3 切租户、清缓存和重连

```ts
async function switchTenant(nextTenantId: string) {
  const previous = authStore.getState().current_tenant?.tenant_id;
  sseManager.closeAll();
  queryClient.cancelQueries({ predicate: (q) => q.queryKey[1] === previous });
  queryClient.removeQueries({ predicate: (q) => q.queryKey[1] === previous });
  lastEventIdStore.remove(previous);

  const response = await api.post("/auth/switch-tenant", {
    tenant_id: nextTenantId,
  });
  authStore.replace(response.data.data);
  queryClient.invalidateQueries({ queryKey: ["tenant", nextTenantId] });
  // 新 SSE 使用新令牌，不带旧 Last-Event-ID。
  sseManager.connectForCurrentTenant();
}
```

部署环境改用冻结契约路径时，只需把适配层改为 `POST /api/tenants/{tenantId}/switch`。页面层不要维护两套切租户逻辑，切换期间的旧响应也不能写入新租户状态。

## 10. 页面最小改造清单

- 登录页：登录成功后一次性写入 AuthSession；`current_tenant` 为空时进入创建/选择流程。
- 全局顶部栏：候选项来自 `tenants`；切换时关闭 SSE、清理旧缓存，收到新会话后刷新页面数据。
- 租户页：接入列表、创建和当前租户；创建请求不发送 `owner_user_id`、`status`、`version`、`tenant_id`。
- 成员页：使用当前租户 ID 拼成员路径，缓存键带租户；不通过查询参数或请求体选择另一个租户。
- KnowledgeFile 页：适配 `records` 和 camelCase 字段；上传、下载、预览走后端路径，不使用 `filePath` 直连。
- Project/Tender 页：列表、统计、版本和详情使用各自旧 VO 字段；所有缓存带租户命名空间。
- AuditTask 页：状态、结果和 `blocks` 请求携带当前令牌；SSE 处理事件外壳，切租户时删除旧 `Last-Event-ID`。
- 所有页面：`permissions` 只用于显隐，真正提交后仍按 403 处理。
- 退出：调用 `/api/auth/logout` 后清空内存和 `sessionStorage` 中的认证状态、租户缓存、SSE 和任务游标。
