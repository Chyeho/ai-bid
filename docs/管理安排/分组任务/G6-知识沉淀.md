## Phase 1：Schema 设计 + 方案文档（W1-W2）

不写代码，只出设计。

1. 阅读 [项目架构设计 §3.7](../../项目架构设计.md) 中 Curator Pipeline 的完整设计
2. 设计 Neo4j 图 Schema：
   - 5 种节点：Law（法规）、Article（条款）、Case（案例）、Risk（风险模式）、ProhibitionRule（禁止规则）
   - 6 种边：has_article、cited_in、found_in、exemplifies、similar_to、amended_by
   - 去重策略：确定性 ID（SHA256 前 8 位），MERGE 自动去重
   - 输出 ER 图 + 节点属性表
3. 写 Curator Pipeline 技术方案：
   - Step 1 CuratorDedupAgent — 去重清洗策略（规则粗筛 + Agent 精判）
   - Step 2 CuratorGraphAgent + CuratorFreshAgent — 实体抽取建图 + 法规时效性检查
   - Step 3 CuratorEmbedAgent — 新实体向量化写入 Qdrant
   - 触发方式（Cron 每月 1 日）、容错机制、回滚策略
4. 与 G8 对齐 `session_snapshots` 表结构

**Phase 1 交付物**：
- Neo4j Schema 设计文档（ER 图 + 节点属性表）
- Curator Pipeline 技术方案文档

## Phase 2：Session 快照存储（W3-W5）

不启动完整 Curator Pipeline，只做快照存储。

1. 与 G8 协作，在 PostgreSQL 中建 `session_snapshots` 表
2. 定义快照 JSON 格式：`docs/schemas/session-snapshot.schema.json`
3. 审核完成后，G4 将 `_curation_mark=true` 的子图快照写入 PostgreSQL
4. 快照标记条件：
   - severity=high + Legal Verify verified
   - 经过 Debate 维持
   - BlindSpot 发现的新风险类型
   - 大模型搜索命中的优质法规/案例
5. 写一个简单规则去重脚本（不调 Agent，纯规则：embedding cosine + exact match）

**Phase 2 交付物**：
- `session_snapshots` 表建好
- Session 快照写入流程跑通
- 规则去重脚本

## Phase 3：Curator Pipeline MVP（W6-W8）

首次启动完整 Curator Pipeline。

1. 实现 CuratorDedupAgent：读取本月 session_snapshots -> 规则粗筛 -> Agent 精判 -> 合并同类/去噪
2. 实现 CuratorGraphAgent：从去重后的记录抽取法律实体 -> 写入 Neo4j（MERGE 去重）
3. 实现 CuratorFreshAgent：检查 Neo4j 已有节点时效性 -> 标记过期法规/案例
4. 实现 CuratorEmbedAgent：新实体向量化 -> 写入 Qdrant
5. 手动触发一次完整 Pipeline，验证四步跑通
6. 目标：月度沉淀有效率 > 60%，Pipeline 耗时 < 20 分钟

**Phase 3 交付物**：
- 4-Agent Curator Pipeline 可运行
- 至少跑通一次完整流程
- Neo4j + Qdrant 双库有新增数据

## Phase 4：自动化+稳定运转（W9-W10）

1. Curator Pipeline 改为 Cron 自动触发（每月 1 日 02:00）

4. 知识飞轮效果评估：统计月度新增数据量、G3 本地命中率变化

**Phase 4 交付物**：
